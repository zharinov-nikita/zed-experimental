# Post-processing may leave the machine, through a session of its own

Post-processing was defined as a rewrite by a local language model, and in practice that meant Ollama, whose resident memory turned out to cost more than the feature was worth on this machine. The obvious replacement — pointing Post-processing at a hosted model through the same provider list the agent panel uses — is closed here: there is a Claude Code subscription and no API key, so no hosted model is reachable that way. What is reachable is the External Agent the user already runs, and it can be asked to rewrite text like anything else. We therefore let Post-processing be configured against an External Agent instead of a language model, and we narrow the fork's locality promise accordingly: Session Audio and the Transcription Engine stay on the machine, the transcript no longer has to.

An agent is not a model, so the rewrite gets a Post-processing Session of its own rather than borrowing the user's conversation. Sessions are cheap where connections are not — Zed already keeps one process per agent and a new session is a single round trip — so the session is per Dictation Session: a Resume sees the text it produced a moment ago, a later dictation sees nothing. The session inherits none of the user's stored options for that agent, both because the model must be selectable independently of whatever the user is chatting with and because those stored options are validated against the chosen model and would be rejected outright. It is also the one place in this fork where an uncontrolled text — a transcript of whatever was said near the microphone — is handed to something holding tools and the user's permissions, and the agent offers no mode that means "no tools at all". So the session is given an empty working directory and the strictest mode available, and every request it makes back to Zed for the filesystem, a terminal, a permission or an answer from the user is refused by session id: a rewrite that tries to act has failed, and the user keeps the raw text.

Two consequences are worth stating because they look like bugs otherwise. Zed cannot know an agent's models before connecting to it — the list arrives with the session — so the model dropdown in the dictation settings is fed from a cache that the first rewrite fills, and is empty with an explanation until then. And the agent, not Zed, owns the list of past sessions, so a Post-processing Session would otherwise surface in the thread history next to real work; it is deleted after use, and filtered out of the list for the agents that cannot delete.
